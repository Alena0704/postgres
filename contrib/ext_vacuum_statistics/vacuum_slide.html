VACUUM Phases & Statistics Collection

How PostgreSQL vacuum works and where ext_vacuum_statistics hooks in

I Scan Table
🔍
Scan every page
Read heap pages sequentially
❄
Prune & freeze tuples
Remove dead versions, freeze old rows
📋
Collect dead TIDs
Store in TidStore for Phase II.
Can't clean heap yet — indexes still point here
II Index Vacuum & Cleanup
✂
Bulk delete
Remove index entries pointing to dead TIDs
🧹
Index cleanup
Reclaim empty pages, update index metapage
📤 Index report → extension
III Table Processing
♻
Table cleanup
LP_DEAD → LP_UNUSED, reclaim space
📊
Table stats summary
pages scanned, tuples frozen, VM updates,
buffer/WAL minus index I/O
📤 Table report → extension
If TidStore fills up mid-scan, Phases I → II → III loop on each batch until the whole table is done.
