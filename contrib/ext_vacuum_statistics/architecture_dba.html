DBA Guide: Configuration & Usage

Everything a DBA needs to install, configure, query, and manage the extension. All interactions are through SQL and postgresql.conf — no C code needed.

Installation

Step-by-step

-- 1. Add to postgresql.conf (requires restart)
shared_preload_libraries = 'ext_vacuum_statistics'

-- 2. Restart PostgreSQL
-- pg_ctl restart -D $PGDATA

-- 3. Create the extension in each database you want views in
CREATE EXTENSION ext_vacuum_statistics;
Note: The extension must be in shared_preload_libraries because it allocates shared memory at server start. Statistics collection works cluster-wide even if you only create the extension in one database — but you need the extension installed in a database to access the views from that database.

Configuration Parameters (GUC)

All settings live under the vacuum_statistics.* namespace. Change them with ALTER SYSTEM SET or directly in postgresql.conf. All are PGC_SUSET (superuser-only, no restart required).

ParameterDefaultWhat it does
vacuum_statistics.enabled on Master switch. When off, no statistics are collected. Existing stats remain until you reset them. Turn it off temporarily to reduce overhead during heavy maintenance windows.
vacuum_statistics.object_types 'all' What level of stats to collect:
'all' — per-table + per-index + per-database aggregates
'relations' — only per-table & per-index (skip DB aggregates)
'databases' — only per-database aggregates (skip individual objects)
vacuum_statistics.track_relations 'all' Filter by relation kind:
'all' — track both user and system tables
'user' — only user-created tables (skip pg_catalog)
'system' — only system catalog tables
vacuum_statistics.collect 'all' Which counter categories to accumulate. Comma-separated list:
buffers blks_read, blks_hit, blks_dirtied, blks_written, I/O timing
wal wal_records, wal_fpi, wal_bytes
general tuples, pages, VM, failsafe, index_vacuum_count
timing total_time, delay_time

Example: 'buffers,timing' — collect only I/O and timing metrics
vacuum_statistics.track_relations_from_list off Whitelist mode for relations. When on, only tables/indexes explicitly added via add_track_relation() are tracked. All others are ignored.
vacuum_statistics.track_databases_from_list off Whitelist mode for databases. When on, only databases explicitly added via add_track_database() produce stats.

Whitelist Management

For large clusters, you may not want to track every table. Use whitelist mode to track only specific objects.

Track Specific Databases

-- Enable whitelist mode
ALTER SYSTEM SET
  vacuum_statistics.track_databases_from_list = on;
SELECT pg_reload_conf();

-- Add a database to track
SELECT ext_vacuum_statistics.add_track_database(
  oid) FROM pg_database
  WHERE datname = 'production';

-- Remove from tracking
SELECT ext_vacuum_statistics.remove_track_database(
  oid) FROM pg_database
  WHERE datname = 'production';

Track Specific Tables/Indexes

-- Enable whitelist mode
ALTER SYSTEM SET
  vacuum_statistics.track_relations_from_list = on;
SELECT pg_reload_conf();

-- Add a table to track
SELECT ext_vacuum_statistics.add_track_relation(
  (SELECT oid FROM pg_database
   WHERE datname = current_database()),
  'my_table'::regclass::oid
);

-- View current track list
SELECT * FROM
  ext_vacuum_statistics.track_list();
Persistence: The whitelist is saved to a file on disk (pg_stat/ext_vacuum_statistics_track.oid) and survives restarts. When a tracked table or database is dropped, the entry is automatically cleaned up.

Querying Statistics

Per-Table Statistics

SELECT relname,
  total_blks_read,
  total_blks_hit,
  pages_scanned,
  tuples_deleted,
  tuples_frozen,
  total_time
FROM ext_vacuum_statistics
  .pg_stats_vacuum_tables
ORDER BY total_time DESC;

All buffer I/O, WAL, timing, pages_scanned, pages_removed, VM updates, tuples frozen/deleted, index vacuum count, missed dead tuples.

Per-Index Statistics

SELECT indexrelname,
  total_blks_read,
  tuples_deleted,
  pages_deleted,
  total_time
FROM ext_vacuum_statistics
  .pg_stats_vacuum_indexes
ORDER BY total_time DESC;

Buffer I/O, WAL, timing, tuples deleted, pages deleted.

Per-Database Statistics

SELECT dbname,
  db_blks_read,
  db_wal_bytes,
  db_total_time,
  interrupts_count
FROM ext_vacuum_statistics
  .pg_stats_vacuum_database;

Aggregated across all tables: buffer I/O, WAL, timing, failsafe & interrupt counts.

Administrative Operations

Reset Statistics

-- Reset ALL statistics
SELECT ext_vacuum_statistics
  .vacuum_statistics_reset();

-- Reset one table (type: 0=table, 1=index)
SELECT ext_vacuum_statistics
  .extvac_reset_entry(
    dboid, relid, type);

-- Reset one database
SELECT ext_vacuum_statistics
  .extvac_reset_db_entry(dboid);

Check Memory Usage

-- How much shared memory used
SELECT
  pg_size_pretty(
    ext_vacuum_statistics
    .shared_memory_size()
  ) AS mem_used;

Each tracked object uses ~232 bytes.
Example: 1000 tables + 2000 indexes = ~700 KB.
