Key Encoding: EXTVAC_OBJID

vacuum_statistics.c : line 119

Each pgstat entry is addressed by (kind, dboid, objid). For relations, objid packs both the relation OID and type into a single uint64:

relid (bits 63..2) Relation OID, shifted left by 2
type (bits 1..0) 0 = PGSTAT_EXTVAC_TABLE
1 = PGSTAT_EXTVAC_INDEX
#define EXTVAC_OBJID(relid, type) \
  (((uint64)(relid)) << 2 | ((type) & 3))

Registered pgstat Kinds

Kind 24: PGSTAT_KIND_EXTVAC_RELATION

  • Key: (dboid, EXTVAC_OBJID(relid, type))
  • One entry per table or index
  • Full PgStat_VacuumRelationCounts
  • Created on first vacuum of that relation

Kind 25: PGSTAT_KIND_EXTVAC_DB

  • Key: (dboid, InvalidOid)
  • One entry per database
  • Only common counters (buffers, WAL, timing)
  • Aggregated across all relations in that DB

Module: Backend-Local Hash Tables (Track Lists)

vacuum_statistics.c : lines 97-98, 124-128

Track lists are stored as backend-local HTAB hash tables, loaded from a shared file on demand (first access per backend). They are not in shared memory — each backend has its own copy, synchronized through the file.

evs_track_databases_hash

HTAB* — key: Oid (single database OID)

[0] 16384 (mydb)
[1] 16385 (testdb)
[...] ...

Lookup: hash_search(hash, &dboid, HASH_FIND, NULL)

evs_track_relations_hash

HTAB* — key: EvsTrackRelKey {dboid, reloid}

Bucket dboid reloid
[0] 16384 24601
[1] 0 (cluster) 1259 (pg_class)
[...] ... ...

Composite key — dboid=0 means cluster-wide (shared catalogs)

Synchronization flow: Backend modifies hash → acquires LWLock → writes full hash to file → releases lock. Other backends detect stale copy on next access → acquire LWLock → reload from file.

Load: evs_track_load_file() — on demand, first access per backend. Reads file under LWLock shared, builds HTAB.
Save: evs_track_save_file() — on every add_track_* / remove_track_*. Acquires LWLock exclusive, writes full file.

  pgstat_accumulate_common_for_db(&shared->stats.common, &params->common);
  pgstat_unlock_entry(entry_ref);
}

ACCUM_IF Macro — Category-Selective Accumulation

vacuum_statistics.c : lines 170-174
#define ACCUM_IF(dst, src, field, cat) \
  do { \
    if (evs_collect_mask & (cat)) \
      (dst)->field += (src)->field; \
  } while(0)

Every counter field is guarded by its category bit. If collect = 'buffers,timing', then evs_collect_mask = 0x9 and WAL/general fields are never incremented — they remain zero in the shared memory entry.

Used in pgstat_accumulate_common() (line 176) and pgstat_accumulate_extvac_stats() (line 197) which adds table/index-specific fields.

Module: Cleanup on DROP

evs_drop_access_hook() — object_access_hook

vacuum_statistics.c : line 455

When a table or database is dropped, PostgreSQL fires the object_access_hook with OAT_DROP. The extension:

  • Checks if the dropped OID is in evs_track_relations_hash or evs_track_databases_hash
  • If found: removes from hash, acquires LWLock, saves updated file
  • The pgstat entry for the dropped object is cleaned up by the pgstat framework automatically (pgstat handles orphaned entries on its own)
  • Chains to prev_object_access_hook if set
