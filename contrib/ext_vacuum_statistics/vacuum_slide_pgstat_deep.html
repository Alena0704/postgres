Cumulative Statistics Collector: Inside

How backend-local counters get flushed to the shared hash table and when

Write Path: Backend → Pending List → Shared Memory
Backend-Local Counters
✏
Each operation increments local struct
INSERT → tuples_inserted++
SELECT → numscans++, blocks_hit++
📝
PgStat_TableStatus
One per table this backend touched.
Lives in backend-local memory.
📚
Transaction-aware
Stack of PgStat_TableXactStatus:
on COMMIT → deltas finalized,
on ABORT → deltas discarded.
Pending List
📋
pgStatPending (dlist)
Linked list of all entries
with unflushed counters in this backend
📦
PgStat_EntryRef
Points to both:
• local pending data
• shared memory entry
Flush to Shared Memory
🔒
Lock per-entry LWLock
Each shared entry has its own lock.
If busy → skip, retry later.
➕
Add local deltas to shared totals
shared.field += local.field
Unlock. Remove from pending list.
📨
Cascade to database stats
Relation flush also creates
a pending database-level entry
Shared dshash Table
🗄
Dynamic shared hash
Key: (kind, dboid, objid)
Grows as new objects appear
⚡
Two-level cache
Backend-local ref hash → shared dshash.
First lookup hits shared, then cached.
When Does Flush Happen?
Trigger
🔁
pgstat_report_stat()
Called after each transaction
in the main query loop
Throttle
⏱
At most once per second
PGSTAT_MIN_INTERVAL = 1000ms
If less than 1s since last flush → skip
⏰
Force after 60 seconds
PGSTAT_MAX_INTERVAL = 60000ms
If pending stats older than 60s → force flush with blocking locks
Normal Flush (non-blocking)
🔓
Try lock, skip if busy
Iterate pending list.
If entry locked by another backend →
skip it, try again next time.
Forced Flush (blocking)
🔒
Wait for lock
After 60s or on shutdown:
block until lock acquired.
Guarantees all stats flushed.
Stats are NOT flushed every second. They are throttled to at most once per second, but only when there are pending entries. Idle backends don't flush.

✅

❌
AtEOXact_PgStat()

How ext_vacuum_statistics Differs
Built-in Relation Stats
📝
Local pending → periodic flush
Counters accumulate in backend,
flushed every ~1s via pending list
🔒
Non-blocking by default
Skip if lock busy, retry next time
📚
Transaction-aware
ABORT discards insert/update/delete counts
ext_vacuum_statistics
⚡
Direct write to shared memory
No pending list. Hook writes to
shared entry immediately via
pgstat_get_entry_ref_locked()
🔒
Always locks (blocking)
Vacuum hook can afford to wait
🚫
Not transaction-aware
Vacuum always commits its work.
No pending_size, no flush_pending_cb.
The extension skips the pending list entirely — it writes directly to shared memory from the vacuum hook. This is simpler and safe because vacuum operations always commit.
